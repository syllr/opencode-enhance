description: 强制重新读取文件或目录，刷新 AI 缓存，以磁盘最新版本为准
---

【刷新缓存模式】AI 此前缓存的文件/目录内容已作废，必须以磁盘当前状态为准。

## 两条核心约定

1. **用户给出的路径必须存在**：用户调用此命令时已经确认路径正确。若磁盘上找不到该路径 = **路径打错** → 立即报错停下（Fast Fail），不要尝试反推、git status、询问
2. **目录内部任何变更都是用户已知的**：用户清楚自己做了什么（新增/修改/删除/重命名等）。AI 只负责接收事实，**不质疑、不复盘、不规划、不提供处置方案**

## 必须执行的步骤

1. **解析路径**：如果用户提供的是相对路径，先用 `pwd` 或工作目录推断出绝对路径，禁止猜测。如果用户没给具体路径（如"那个配置文件"）→ 先要求具体路径再继续
2. **Fast Fail 校验**：用 `ls` 或 Glob 确认每个目标路径**存在**（文件或目录均可）。不存在 → 立即停下，输出：
   ```
   🔴 refresh 中断：路径不存在
   - <不存在的路径>
   可能是路径打错了，请确认后重新调用。
   ```
   **禁止**反推：不要查 git history、不要猜测是否被删除、不要询问用户意图
3. **强制重新读取**：
   - 文件：逐个调用 `Read` 工具重新读取（绝对路径）
   - 目录：先 `ls` 列出完整条目，再对**目录里每一个条目**（含新增文件/子目录）分别调用 `Read` 工具（绝对路径）
4. **丢弃旧缓存**：在所有后续的 Edit / Write / ast_grep_replace 操作中，**必须以本次重新读取到的内容为唯一事实来源**，禁止以对话历史中的旧版本内容为修改依据
5. **确认刷新完成**：输出 `✅ 已刷新：<路径列表>`，**仅此而已**，然后停下等用户指令

## 硬性禁止

- ❌ 禁止在重新读取前对目标执行任何 Edit / Write 操作
- ❌ 禁止基于对话历史中的旧内容推断文件当前状态
- ❌ 禁止把"我觉得之前看到的是 X"作为修改依据
- ❌ 禁止只读取部分文件就声称"已刷新整个目录"
- ❌ **禁止扫描下游引用**：不要主动 grep/Read 与 refresh 目标相关的引用方文件（README、设计文档、调用方代码等）。那是用户的下一步，不属于本次 refresh

## 输出示例

```
✅ 已刷新：
- /Users/yutao/project/src/auth.ts
- /Users/yutao/project/src/auth/handlers/

请告知后续操作。
```

如目录有新增条目：

```
✅ 已刷新：
- /Users/yutao/project/src/auth.ts
- /Users/yutao/project/src/auth/handlers/（含新增条目 oauth.ts、payment.ts，均已读取）

请告知后续操作。
```
