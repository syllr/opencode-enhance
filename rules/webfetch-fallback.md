# WebFetch 降级策略规则

## 核心规则

当 `webfetch` 工具无法获取网页内容时，根据错误类型决定是否使用 Playwright MCP 作为备选方案。

## 错误分类与处理策略

### 1. 页面本身的问题 ❌ 不走 Playwright

**错误类型**：HTTP 4xx/5xx（403 除外）、重定向循环、明确的错误页面

**403 特殊处理**：检查响应内容。**若 webfetch 未返回响应正文（仅返回状态码），无法区分 403 原因时，按类别 1 处理（直接报告错误）**。若响应正文存在：包含反爬特征（challenge/captcha/CDN 拦截）→ 归入类别 3；为明确权限拒绝 → 归入本类

**处理**：直接报告错误，不重试

### 2. 网络无法连接 ✅ Playwright 无头模式

**错误类型**：Connection refused/timeout、DNS 失败、SSL/TLS 错误、HTTP 407、其他连接层失败

**处理**：使用 Playwright MCP 无头模式重试（可走代理）

### 3. 需要登录或反爬虫 ✅ Playwright 有头模式

**错误类型**：登录/验证码页面、HTTP 401/429、403+反爬特征、200 但内容异常（**任一满足即触发**：① <100字符且无 JSON/HTML/XML 结构 ② 含 password input ③ Cookie 弹窗/登录引导阻断）

**处理**：

1. 使用 Playwright MCP 有头模式
2. 提示用户：`检测到需要登录或反爬虫验证，请在浏览器中手动操作。完成后请回复确认（如「继续」「好了」「ok」「done」任一即可）`
3. 等待用户回复**肯定确认**（如「继续」「好了」「ok」「完成」「done」等任一即可）后获取内容
4. **AI 只负责获取内容，不负责绕过安全机制**。具体禁止行为（无论用户是否主动要求）：
   - 禁止填入任何表单字段（含用户名、密码、验证码、邮箱、一次性 token）
   - 禁止点击含 "Sign in" / "Login" / "验证" / "Continue" / "人机验证" 文字或对应图标的按钮
   - 禁止执行自动登录脚本或调用验证码识别服务
   - 禁止要求用户粘贴密码/cookie/token 到对话中（合规做法：用户在浏览器手动完成后，告知 AI「已登录」即可）

## 执行步骤

1. 尝试 `webfetch` 获取内容
2. 若失败，按上述分类判断错误类型
3. 按对应策略处理
4. 若 Playwright 也失败，**结构化报告**：原始 URL + webfetch 错误摘要 + Playwright 错误摘要；建议用户：1) 手动访问确认 2) 检查网络/凭据 3) 提供替代 URL；**不再重试**

## 注意事项

1. URL 必须用双引号包围
2. 操作完成后必须关闭浏览器（`playwright_browser_close`）；headed 模式下额外关闭浏览器上下文，下次使用新上下文
3. **Playwright MCP 不可用**（未配置 / 启动失败 / 连接断开）时，立即报告"webfetch 失败 + Playwright 不可用"，不再重试
4. 无桌面环境检测：若环境变量 `DISPLAY` 和 `WAYLAND_DISPLAY` 均为空（如 CI / 远程服务器），有头模式自动降级为无头模式并提示用户
