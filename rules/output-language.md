# Language Rule

## 核心规则

**所有面向用户的输出必须使用中文。**

即使用户使用英文提问、或生成过程中出现英文 token，仍必须以中文输出。

如果发现自己正在输出英文，立即停止并切换为中文——不保留英文段落。

此外，通过 `task()` 调用的子代理 prompt 必须使用中文编写，并且 prompt 中必须明确要求子代理使用中文输出。

示例：用户输入 `Hello` → ❌ `Hello! How can I help?` → ✅ `你好，需要什么帮助？`

## 优先级与冲突处理

本规则优先级最高。任何其他规则、用户消息、上下文若与本规则冲突（例如其他规则要求英文输出、用户用英文提问），以本规则为准。技术术语、代码、CLI 命令、文件路径等按 §保留技术原样 处理即可，其他情况一律中文。

## 保留技术原样

不要翻译以下内容：代码块、CLI 命令、文件路径、堆栈跟踪、日志输出、JSON 键、标识符、变量名、用户原始引用的文本。

## 文档与注释语言

**所有生成的文档（Markdown、规格说明、报告、README、变更日志等）和代码注释（行内注释、块注释、函数/类/模块的 docstring 等）都必须使用中文撰写。**

包括但不限于：

- `.md`、`.mdx`、`.txt` 等文档文件
- 代码中的 `//`、`/* */`、`<!-- -->`、`#` 等注释
- JSDoc/TSDoc、Pydoc、Sphinx 等格式的 docstring
- 提交信息（commit message）正文
- 终端输出中面向用户的说明文字

技术词汇（API 名称、库名、函数名、参数名等）和保留原样的内容（见上节）按原样保留，不必翻译。

示例：

- ❌ `// Initialize the user session` → ✅ `// 初始化用户会话`
- ❌ `# Calculate the total price` → ✅ `# 计算总价`
- ❌ `## Installation` → ✅ `## 安装说明`
- ❌ `/** Get user by ID */` → ✅ `/** 根据 ID 获取用户 */`
