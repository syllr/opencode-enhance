# 远程执行规则（remote-shell）

## 核心规则

当用户需要在远程服务器上执行命令时，**必须优先使用 `remote-shell` CLI 工具**。

禁用以下任何工具或方法作为首选方案：

- `ssh` 命令及其所有变体
- `sshpass` 命令（无论是否配合 `ssh` 使用）
- `expect`、`putty`、`plink` 等 SSH 客户端
- 任何编程语言的 SSH 库（`paramiko`、`fabric`、`pexpect`、`JSch` 等）
- 任何脚本封装（`bash -c "ssh ..."`、`python -c "import paramiko..."` 等）

**AI 不得以"规则没提到 XXX 工具"为由跳过 `remote-shell`**。如果不确定某个工具是否被禁止，默认假设被禁止。

**CLI 用法**：执行前先运行 `remote-shell list` 和 `remote-shell --help` 了解可用主机和完整参数。

**退出码获取**：执行 `remote-shell` 后立即检查 `$?`（如 `remote-shell <别名> '<命令>'; echo "EXIT:$?"`），按上表降级条件精确判断。

---

## 降级回退机制

**降级必须基于 exit code 精确判断**——禁止"remote-shell 失败就直接切 sshpass"的经验式跳过。降级条件见下表。

### 降级触发条件（按 exit code）

| exit code   | 场景                                            | 是否降级      | 降级策略                                                          |
| ----------- | ----------------------------------------------- | ------------- | ----------------------------------------------------------------- |
| **0**       | 成功执行                                        | ❌ 不降级     | 直接返回结果给用户                                                |
| **1**       | 连接拒绝/主机不可达/连接丢失                    | ✅ 降级       | 使用 sshpass 重试                                                 |
| **2**       | SSH 握手超时                                    | ✅ 降级       | 使用 sshpass 重试                                                 |
| **5**       | 认证失败/配置错误                               | ✅ 降级       | 使用 sshpass + 密码表重试                                         |
| **126/127** | 权限不足/命令未找到（`remote-shell` 不在 PATH） | ⚠️ 降级前报告 | ①向用户报告"remote-shell 不可用或权限不足"；②询问是否继续 sshpass |
| 其他非以上  | 未预期的内部错误                                | ⚠️ 谨慎降级   | ①向用户展示完整 stderr；②**不等待用户回复**，立即用 sshpass 重试  |

### 降级执行

```bash
sshpass -p '<密码>' ssh -o StrictHostKeyChecking=no <用户>@<主机> -p <端口> '<命令>'
```

**密码遮蔽要求**：执行 sshpass 时，**禁止在向用户展示的工具输出中回显完整命令行**（密码会出现在 stdout/stderr 中）。向用户展示时需截断为 `sshpass ... ssh <用户>@<主机> '<命令摘要>'` 格式，或仅展示退出码 + 操作摘要。

**密码表**（仅限 sshpass 降级场景使用）：

| 主机别名   | sshpass 密码     | 完整连接信息          |
| ---------- | ---------------- | --------------------- |
| 远程开发机 | dev1110          | dev@115.190.154.64:22 |
| 4090-24G   | A1Ck720683VHSGp5 | root@106.75.44.44:23  |

**禁止在回复中向用户展示密码**。

### 降级约束

- 每次发起新的远程命令，**必须重新从 `remote-shell` 开始尝试**，不允许因上次 sshpass 成功而跳过
- 如果 `remote-shell` 和 `sshpass` 都失败，**停止尝试**，将两次失败信息展示给用户并给出排查建议（建议用户：①手动 `ssh` 验证连通性；②确认密码表条目是否过期；③检查是否需要跳板机）
- **禁止忽略 exit code 盲目降级**：必须先读取退出码，按上表判断

## 用户选择优先

如果用户明确说了"如果太麻烦就把命令给我"等类似表述（英文场景：`just give me the command` / `let me run it myself` / `show me what to run` / `I want to execute it locally`）：**优先直接给出命令**，格式为 `remote-shell <别名> '<命令>'`，让用户自行执行。

> ⚠️ **在降级流程中，不要因为退出码而反复询问用户**——只在 `remote-shell` 不可用（126/127）或用户主动表示退出时，才建议用户自行执行（用户主动要求给命令的，按上方 §用户选择优先 处理）。
